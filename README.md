# WCET Analyzer — Шаг ПИД-регулятора

Лабораторная работа №2 по курсу «Системы реального времени» (СРВ).
Консольное приложение на Python для оценки **наилучшего (BCET)** и
**наихудшего (WCET)** времени выполнения фрагмента кода, реализующего
один шаг ПИД-регулятора: чтение уставки, вычисление управляющего
воздействия, вывод значения на привод.

Вариант задания: **«Шаг ПИД-регулятора: чтение уставки, вычисление,
вывод на привод»**.

## Описание задачи

Для заданного фрагмента программы и модели процессора необходимо:

1. Вычислить лучшее и худшее время выполнения каждой операции.
2. Просуммировать BCET и WCET по всему фрагменту.
3. Рассчитать коэффициент недетерминизма `K = WCET / BCET`.
4. Разложить вклад в WCET по источникам — промахи кэша и ошибки предсказания переходов.
5. Проверить, укладывается ли фрагмент в заданный дедлайн в худшем случае.

Модель времени выполнения операции:

```
BC(op) = base_cost
WC(op) = base_cost + memory_accesses * cache_miss_penalty
                    + branches * branch_mispredict_penalty
```

## Формат входных данных

Файл [`data/pid_config.json`](data/pid_config.json) содержит два блока:
параметры модели процессора и список операций фрагмента.
**Магические числа в коде отсутствуют** — все параметры задаются только здесь.

<details>
<summary>Пример структуры JSON</summary>

```json
{
  "processor": {
    "base_cost": 1,
    "cache_miss_penalty": 20,
    "branch_mispredict_penalty": 12,
    "deadline": 160
  },
  "operations": [
    {
      "name": "Чтение уставки (SP)",
      "op_type": "MEM_READ",
      "memory_accesses": 1,
      "branches": 0
    }
  ]
}
```

</details>

**Блок `processor`:**

| Поле | Тип | Описание |
|---|---|---|
| `base_cost` | int | Базовая стоимость операции, тактов |
| `cache_miss_penalty` | int | Штраф за промах кэша, тактов |
| `branch_mispredict_penalty` | int | Штраф за ошибку предсказания перехода, тактов |
| `deadline` | int | Директивный срок выполнения фрагмента, тактов |

**Блок `operations` (список объектов):**

| Поле | Тип | Описание |
|---|---|---|
| `name` | str | Название операции |
| `op_type` | str | Тип: `MEM_READ`, `MEM_WRITE`, `ALU_*`, `BRANCH_COND` |
| `memory_accesses` | int | Количество обращений к памяти |
| `branches` | int | Количество условных переходов |

## Реализованные функции

| Функция | Сигнатура | Назначение |
|---|---|---|
| `best_case` | `(op, model) -> int` | BCET одной операции |
| `worst_case` | `(op, model) -> int` | WCET одной операции |
| `bcet` | `(fragment, model) -> int` | Суммарное BCET фрагмента |
| `wcet` | `(fragment, model) -> int` | Суммарное WCET фрагмента |
| `nondeterminism_ratio` | `(fragment, model) -> float` | Коэффициент `WCET / BCET` |
| `source_breakdown` | `(fragment, model) -> dict` | Вклад базы/памяти/ветвлений в WCET |
| `load_configuration` | `(file_path) -> tuple` | Загрузка модели и операций из JSON |
| `display_results` | `(fragment, model) -> None` | Вывод таблицы и заключения в консоль |

> Модели `Operation` и `ProcessorModel` реализованы как неизменяемые (`frozen=True`) `@dataclass`.
